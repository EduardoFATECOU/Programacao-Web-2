Build e Releases com Vite

Processo de build, otimizações e deploy de aplicações React

Estrutura do Projeto

17_Build_Releases/
├── index.html          # HTML raiz
├── package.json        # Dependências e scripts
├── vite.config.js      # Configuração do Vite
├── public/             # Assets estáticos
└── src/
    ├── main.jsx        # Entry point
    └── App.jsx         # Componente principal

Comandos

# Desenvolvimento (servidor local)
npm run dev

# Build de produção (gera pasta dist/)
npm run build

# Preview do build localmente
npm run preview

Após o build, a pasta dist/ conterá:

  • index.html — HTML final
  • assets/index-abc123.js — JS minificado
  • assets/index-xyz456.css — CSS minificado

Configuração do Vite (vite.config.js)

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  build: {
    outDir: 'dist',          // Pasta de saída
    minify: 'esbuild',       // Minificador (esbuild é mais rápido)
    sourcemap: false,         // Sem mapas de origem em produção
    rollupOptions: {
      output: {
        manualChunks: {      // Separa bibliotecas em chunk próprio
          vendor: ['react', 'react-dom'],
        },
      },
    },
  },
  server: {
    port: 3000,              // Porta do servidor dev
    open: true,               // Abre navegador automaticamente
  },
});

Processo de Release

1
Desenvolvimento
Código no branch feature/*
2
CI (Testes)
Testes automáticos (GitHub Actions)
3
Build
npm run build → dist/
4
Deploy
Vercel, Netlify, S3, etc.

Boas Práticas

  • Sempre teste o build localmente antes do deploy
  • Use CI=true npm test em pipelines CI/CD
  • Mantenha variáveis de ambiente em .env (não versionado)
  • Configure sourcemap: false em produção
  • Use code splitting para reduzir o bundle inicial
  • Faça lazy loading de rotas com React.lazy()
  • Ative compression (Gzip/Brotli) no servidor
